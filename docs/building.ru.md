# Сборка и проверка из исходников

[English](building.md) · [Русский](building.ru.md) · [README](README.ru.md)

## Что нужно

- Windows, PowerShell 5.1 и компилятор C# из .NET Framework 4.x (`Framework\v4.0.30319\csc.exe` внутри папки Windows).
- Локальная **Steam Terraria 1.4.5.8** и **Microsoft XNA Framework 4**. Один раз запустите обычную игру для установки компонентов.
- Интернет для первой загрузки закреплённого Mono.Cecil или заполненный корректный кэш `.deps`.

Python, tModLoader, Visual Studio и отдельный .NET SDK не нужны. Перед запуском прочитайте скрипты. Недостающие компоненты игры не заменяйте DLL со случайных сайтов.

## Сборка

В PowerShell из корня репозитория:

```powershell
powershell -NoProfile -File .\scripts\build.ps1
```

Если игра не найдена автоматически:

```powershell
powershell -NoProfile -File .\scripts\build.ps1 -TerrariaExe 'D:\SteamLibrary\steamapps\common\Terraria\Terraria.exe'
```

Скрипт скачивает только закреплённый [Mono.Cecil 0.11.6](https://www.nuget.org/packages/Mono.Cecil/0.11.6) с NuGet, проверяет SHA-256 пакета и DLL по константам из [уведомлений](../THIRD-PARTY-NOTICES.md), компилирует модуль и лаунчер и упаковывает разрешённый список файлов. Обычная сборка не устанавливает мод в игру.

Результат:

```text
dist/HighFpsSupport.exe
dist/HighFPS.Support.dll
dist/Mono.Cecil.dll
dist/SHA256SUMS.txt
release/HighFPS-Support-1.1.0-Terraria-1.4.5.8-win-x86.zip
release/SHA256SUMS.txt
```

В `dist` и ZIP входят документация, лицензии, проверка хэшей, исходники и скрипты сборки/тестов. Каждая сборка записывает свои хэши в `release/release-hashes.md`. Опубликованные суммы в `docs/release-hashes.md` остаются прежними. В архиве находятся хэши бинарников без циклического хэша самого ZIP.

Если Windows блокирует скрипты, сначала прочитайте исходник и подключаемый `scripts/common.ps1`. На своём компьютере, если это разрешено вашей политикой, можно разрешить выполнение проверенной сборки только этому процессу PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

Политика всей системы не меняется; принудительную политику организации команда не обходит. Такой же параметр одного процесса можно использовать для изученных скриптов проверки ниже. Ручная проверка через `Get-FileHash` не запускает скрипты проекта.

## Проверки

```powershell
powershell -NoProfile -File .\scripts\verify-release.ps1
powershell -NoProfile -File .\scripts\verify-release.ps1 -Directory .\release
powershell -NoProfile -File .\scripts\test.ps1
```

`test.ps1` собирает проект и проверяет патч, установку, JIT, интерполяцию и интерфейс на отдельной копии локальных файлов игры. Установка в рабочую папку игры не требуется. `-SkipBuild` использует готовую сборку, `-TerrariaExe` задаёт путь явно. Тестовые файлы могут содержать закрытые данные игры — не публикуйте их.

Проверка интерфейса и локализации без установленной игры:

```powershell
powershell -NoProfile -File .\scripts\test-launcher.ps1
```

GitHub workflow выполняет проверки без игры, проверку синтаксиса PowerShell и защиту от отслеживаемых закрытых бинарников. Полный набор с Terraria/XNA без этих компонентов там не запускается. Автотесты не подтверждают плавность реальной игры: отдельно проверяйте движение, прицел, меню, телепортацию и при необходимости мультиплеер на мониторе с высокой частотой.

## Что даёт самостоятельная сборка

Вы сами выбираете проверенные исходники и зависимости, которые запускаете. Это не доказывает автоматически, что скачанный релиз собран из тех же исходников. **Побитовая воспроизводимость не заявлена:** идентификаторы сборок .NET Framework и метаданные ZIP могут менять хэши. Сравнивайте исходники, поведение и закреплённые зависимости; совпадение хэша локального EXE с релизом не ожидается.
